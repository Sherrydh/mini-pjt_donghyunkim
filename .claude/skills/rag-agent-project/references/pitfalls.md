# 실수 기록 — 증상, 원인, 해결

실제 프로젝트에서 시간을 잃은 순서대로가 아니라 영역별로 묶었다. 같은 증상을 보면 여기부터 찾는다.

## 기획·평가 세트
| 증상 | 원인 | 해결 |
|---|---|---|
| 몇몇 케이스가 어떤 버전에서도 통과 못 함 | 세트를 코퍼스보다 먼저 써서 근거로 충족 불가, 또는 기준이 주관적("짧게") | 데이터 구축 후 세트-코퍼스 대조. 평가 후 발견했다면 한계로 기록(기준 이동 의심 회피) |
| 사용자 수준 표현("체르니 100번")에 답 못 함 | 사용자 언어 ↔ DB 기준(Henle 등급) 브리지 데이터 부재 | 대응 기준 문서를 코퍼스에 추가, 추천 의도면 자동 검색 |
| 되묻기가 명확한 질문에도 나옴(과잉 되묻기) | 세트에 모호한 질문만 있어 검출 못 함 | "되묻지 말아야 할 명확한 질문" 케이스 추가, 되묻기 횟수 상한(1회) 후 기본 해석 + 가정 명시 |
| seed/스펙 단계를 건너뜀 | 구현을 서두름 | 인터뷰 → seed → 구현 순서 유지 |

## 에이전트 동작
| 증상 | 원인 | 해결 |
|---|---|---|
| 필요한 도구를 안 부르고 사전 지식으로 답 | 프롬프트가 도구 사용을 "권장"만 함, 복합 의도 미분해 | planner(의도별 필수 도구) + check(대조 후 1회 재요청) |
| 검색은 했는데 답에서 항목 누락 | 요구 항목 체크리스트 없음 | must_cover + finalize 검수, 보조 검색 항목 자동 합치기 |
| 필요한 섹션이 검색 순위 밖 | 질문 표현과 섹션 표현 불일치 | coverage_queries + prefetch 강제 실행 |
| "수준을 정확히 모르므로" 문구가 수준을 말했는데도 나옴 | 표기 강제 규칙이 조건 없이 적용 | 규칙에 조건(수준을 안 줬을 때만) 명시 |
| "K.545요"를 연습 중 곡으로 오저장 | 추출기가 대화 맥락 없이 발화만 봄 | 직전 에이전트 질문을 함께 전달 |
| 길이 제한 넣었더니 지어내기·지표 하락 | 근거 없는 임의 제약 | 스펙에 없는 제약은 넣지 않음, 적응형 길이도 효과 없어 되돌림 |

## HITL·LangGraph
| 증상 | 원인 | 해결 |
|---|---|---|
| 되묻기 HITL이 별 이점 없음 | 재개 시 노드 재실행, 기억 없음 | 되묻기는 대화 턴, HITL은 저장 승인에만 |
| 승인 대기 중 새 질문 → 옛 카드 승인 시 직전 답 반복 또는 새 제안 승인 | 새 입력이 대기 interrupt를 폐기, resume에 제안 식별자 없음 | proposal_id + get_state로 대기 확인 + expired 응답 + 화면 카드 만료 |
| interrupt 노드에서 LLM이 두 번 호출 | 재개 시 노드가 처음부터 실행 | 추출(propose)과 승인(approve) 노드 분리, approve엔 LLM 없음 |

## 검색·인프라
| 증상 | 원인 | 해결 |
|---|---|---|
| Chroma KeyError(병렬 평가 중) | 클라이언트 동시 생성 경합 | 공유 PersistentClient(lru_cache) + 락 |
| 리랭킹 KeyError | 근거 0~1건이면 점수 미계산 | 기본 점수 1.0 |
| Bedrock ThrottlingException / 일일 한도 소진 | `us.` 프로필 일일 토큰 한도 | adaptive retry, `global.` 추론 프로필로 전환, 오류 실행은 INVALID 표시 |
| 평가 중 노트북 종료로 결과 유실 | 마지막에 한 번만 저장 | 케이스별 inprogress 저장 |
| ragas 설치 실패 (Python 3.14) | scikit-network wheel 없음 | 의존성만 빼고 --no-deps 설치 + import shim, README에 기록 |

## 평가기
| 증상 | 원인 | 해결 |
|---|---|---|
| 출처를 달았는데 불충족 | judge가 출처 권위를 판단 | 먼저 그 URL이 contexts에 있었는지 확인(없으면 환각), 있었으면 "표기 여부만" 규칙 |
| RAGAS faithfulness·relevancy가 이유 없이 낮음 | 거절·"자료 없음" 답까지 계산 | positive·edge만 계산, 제외 건수 리포트에 기록 |
| judge 통과율이 사람 판단보다 후함 | 서비스와 같은 모델이 자기 답을 채점 | judge 고정 + 통과 샘플 사람 확인, 리포트에 judge 모델 기록 |
| DB에 있는 값을 judge가 틀렸다고 함 | judge에 contexts 미제공 | contexts 제공 + 사전 지식 반박 금지 |
| answer_relevancy 0.4대 | 영어로 질문 역생성 | 언어 힌트 |
| context_precision 급락 | 부분 근거 0점 + 근거 순서 | 부분 useful 힌트 + 리랭킹 |
| 측정 스크립트가 환각 3건 오탐 | 같은 작품번호, 하이픈, 짝짓기 범위 | 문맥 구분·정규화·같은 절 짝짓기 |

## 작업 도구·환경 (Windows)
| 증상 | 원인 | 해결 |
|---|---|---|
| heredoc·문자열 이스케이프로 패치가 깨짐 | 셸 따옴표 중첩 | 패치 스크립트를 스크래치 파일로 쓰고 python으로 실행(assert로 치환 개수 확인) |
| 프롬프트에 `' + '` 같은 쓰레기 문자열 삽입 | 문자열 치환 실수 | 치환 후 diff 확인 |
| run.sh가 CRLF로 바뀌어 bash 실행 불가 | Windows autocrlf | `.gitattributes`에 `*.sh text eol=lf` |
| 테스트는 Haiku로 했는데 기본값은 Sonnet | config 기본값 미갱신 | 공식 평가 모델 = 코드 기본값 |
| 코드 수정 후 README 줄 번호 불일치 | 줄 번호 하드코딩 | 제출 전 `grep -n "^def "`로 대조 |
| 이력 파일이 커서 컨텍스트가 급감(자동 요약) | 긴 세션 | history.md에 결정·수치를 남겨 요약 후에도 이어갈 수 있게 |
